# COBOL Account Management System Test Plan

This test plan documents the current COBOL business logic and behavior so business stakeholders can validate expected outcomes before and during modernization to Node.js.

| Test Case ID | Test Case Description | Pre-conditions | Test Steps | Expected Result | Actual Result | Status (Pass/Fail) | Comments |
|---|---|---|---|---|---|---|---|
| TC-001 | Application starts and displays the main menu | Application is compiled successfully (`accountsystem` executable exists). | 1. Run `./accountsystem`. | Main menu is displayed with options 1-4 and prompt `Enter your choice (1-4):`. | TBD | TBD | Validates startup flow and menu text. |
| TC-002 | View current balance (initial state) | Application is running in a new session. No prior credit/debit in this run. | 1. At menu, enter `1`.<br>2. Observe output. | System displays `Current balance:` with initial value `1000.00`. | TBD | TBD | Confirms initial stored balance and read operation. |
| TC-003 | Credit account with a valid amount | Application is running in a new session (or record current balance before test). | 1. At menu, enter `2`.<br>2. When prompted, enter `250.50`.<br>3. Observe output. | System displays `Amount credited. New balance:` and balance increases by 250.50 from previous balance. | TBD | TBD | Validates credit calculation and write-back to storage. |
| TC-004 | Debit account with sufficient funds | Application is running. Balance is at least 200.00 (for example, initial 1000.00). | 1. At menu, enter `3`.<br>2. When prompted, enter `200.00`.<br>3. Observe output. | System displays `Amount debited. New balance:` and balance decreases by 200.00 from previous balance. | TBD | TBD | Validates debit calculation when funds are sufficient. |
| TC-005 | Debit account with insufficient funds | Application is running. Current balance is known and lower than attempted debit amount. | 1. At menu, enter `3`.<br>2. When prompted, enter an amount greater than current balance (for example, `999999.99`).<br>3. Observe output. | System displays `Insufficient funds for this debit.` and balance is not changed. | TBD | TBD | Confirms overdraft prevention rule. |
| TC-006 | Invalid menu option handling | Application is running and waiting for menu choice. | 1. Enter an option outside 1-4 (for example, `9`).<br>2. Observe output.<br>3. Observe next prompt. | System displays `Invalid choice, please select 1-4.` and returns to main menu prompt. | TBD | TBD | Validates invalid choice branch and loop continuation. |
| TC-007 | Exit option terminates application | Application is running and waiting for menu choice. | 1. Enter `4`.<br>2. Observe output and process state. | System prints `Exiting the program. Goodbye!` and program terminates. | TBD | TBD | Validates controlled shutdown path. |
| TC-008 | Balance persists across operations within same run | Application is running in a fresh session. | 1. Enter `2` and credit `100.00`.<br>2. Enter `1` to view balance.<br>3. Enter `3` and debit `50.00`.<br>4. Enter `1` to view balance again. | After credit, displayed balance is previous + 100.00. After debit, displayed balance is (previous + 100.00 - 50.00). | TBD | TBD | Confirms data read/write consistency during one program execution. |
| TC-009 | Exact-balance debit is allowed | Application is running with known balance (for example, 1000.00 in fresh run). | 1. Enter `3`.<br>2. Enter debit amount equal to current balance.<br>3. Enter `1` to view resulting balance. | Debit succeeds (no insufficient funds message). New balance becomes `0.00`. | TBD | TBD | Verifies boundary condition for `>=` comparison in debit logic. |
| TC-010 | New run resets to initial balance | Complete one run with balance-changing operations, then exit. | 1. In first run, perform credit/debit to change balance.<br>2. Exit with option `4`.<br>3. Start program again with `./accountsystem`.<br>4. Enter `1` to view balance. | Balance on new run is re-initialized to `1000.00`. | TBD | TBD | Reflects current in-memory storage behavior (non-persistent across process restarts). |
